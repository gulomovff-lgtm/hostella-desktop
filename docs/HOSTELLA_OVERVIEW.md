# Hostella — структура и возможности системы

**Версия:** v0.13.0 · **Составлено:** 17.08.2026

Система управления хостелом для двух филиалов в Ташкенте: настольное приложение для касс, сайт с ИИ-ботом бронирования и интеграция с госсистемой e-mehmon — единый контур.

---

## 1. Архитектура

Три самостоятельные части, связанные через Firebase и HTTP-колбэки:

```
┌─────────────────────────┐      ┌──────────────────┐      ┌──────────────────────────┐
│ 🖥 Приложение (Electron) │ ⇄   │ ☁️ Firebase       │  ⇄   │ 🌐 hostella.uz (PHP+MySQL)│
│  интерфейс кассира       │      │  Firestore        │      │  бронирование, ИИ-бот     │
│  фоновые окна e-mehmon   │      │  Cloud Functions  │      │  crm-callback.php         │
└───────────┬─────────────┘      └──────────────────┘      └────────────┬─────────────┘
            │                                                            │
            ▼                                                            ▼
   🏛 e-mehmon.uz (госрегистрация)                          ✈️ Telegram (уведомления гостям
                                                                и владельцу)
```

**Стек приложения:** Electron 28 (main/preload/renderer, IPC), React 18 + Vite, Tailwind; Firestore (именованная БД `hostella`, анонимная авторизация); electron-builder → GitHub Releases → авто-обновление касс (подписанный установщик NSIS).

**Стек сайта:** PHP + MySQL на shared-хостинге; Telegram-бот на webhook с ИИ (Blackbox/OpenAI) и Whisper для голосовых; оплата Payme/Click; письма; QR-страницы.

**Надёжность:** офлайн-очередь платежей и Telegram-сообщений; отмена действий (↩) для заселения, оплаты, продления, расхода, активации брони; ежедневный автобэкап Firestore; аудит-лог всех операций.

## 2. Возможности по разделам

### 👤 Гости и заселение
- Заселение в 3 шага: комната/койка → данные → оплата
- На койках видно жильца, долг (💰) и просроченных гостей (⏰)
- Скан паспорта (MRZ + ИИ-распознавание фото)
- Тарифы: стандарт / пакет (мин. дней, невозвратный); оплата в UZS/USD; оплата балансом клиента
- Продление, перенос дат, урезание дней, сплит с паузой, переезд (оплата закрывает прожитые дни в первую очередь)
- Выселение: возврат / на баланс / смешанно; авто-выселение просроченных
- Долги: создание, погашение, долговые записи без комнаты

### 📅 Брони
- Заявки с сайта и Telegram-бота: бейдж источника (🌐/✈️), код HS-XXXXXX, сумма, комментарий
- Большое окно-напоминание: при новой брони и каждые 6 часов, закрытие только вручную; телефон гостя крупно
- ИИ-сводка переписки для чат-броней: доп. пожелания, договорённости, язык гостя, советы для звонка
- Групповые брони: заселение по одному со своим паспортом, прогресс «заселено X из Y»
- Залог по брони без паспортных данных; авто-перенос залога в запись гостя при заселении
- Паспорт и дата рождения обязательны при заселении брони; активация — с отменой в ↩
- Booking.com через iCal-синхронизацию

### 🏛 e-mehmon (госрегистрация)
- Полный автомат для граждан Узбекистана: регистрация после первой оплаты, в фоне, без окон
- Иностранцы — мастер с автозаполнением формы
- Фоновый вывод (одиночный и массовый), авто-вывод по истечении срока регистрации
- Сверка каждые 5 минут: ставит И снимает отметки по факту списка /listok
- Киоск-интерфейс для кассиров: Вывести / Оформить / Скоро истекают / Всё в порядке
- Пометка «Ошибка в паспортных данных» (снимается при исправлении), плашка «хвостов» на всех экранах

### 💵 Финансы
- Смены: открытие/закрытие, отчёт в Telegram, пересдача кассы
- Одна открытая смена на филиал: пока кассир работает, второй войти не может (замок в Firestore + транзакция)
- Передача смены (подмена) из окна «Закрытие смены»: сутки и ЗП делятся 50/50, вся касса и поступления переходят принявшему — он сдаёт один общий отчёт за сутки
- Админ может разделить уже отработанную смену 50/50 одним кликом (напарник подставляется, если он один)
- Расходы: категории с иконками, свои категории по филиалам, повторяющиеся, USD-курс
- Отчёты и аналитика: выручка, загрузка, каналы, экспорт Excel
- Цены по комнатам: минимумы (Ф1: комн.4 — 60к, 1–2 — 65к, 3/5/6 — 70к, 7 — 80к; Ф2 — 65к), пакеты, сезоны по датам
- Понижение цены — только с одобрения администратора в Telegram (отдельный бот)
- Белый список постоянных клиентов, промокоды, реферальная программа

### 📋 Договоры / бригады (ManualStay)
- Ставка за человеко-ночь × участники (авто из проживаний) и ручные периоды
- Бригады по специальностям, мини-календарь периодов
- Доп. расходы в свободной форме с ценами (входят в начислено/долг/отчёты)
- Перенос долга/переплаты между договорами (парные позиции, без искажения кассы, опция «и в архив»)
- Жизненный цикл: активен → завершён → архив → «Вернуть» → «Возобновить»
- Отчёты по месяцам, объединённая оплата нескольких договоров
- Удаление позиций и периодов — только с подтверждением; переносы удаляются парой

### 👥 Клиенты
- База клиентов: авто-пополнение при заселении, дедупликация, нормализация стран
- Баланс (возвраты «на счёт»), пополнение. Переплата во время проживания на баланс **не** зачисляется — она гасит начисление при продлении, а на баланс уходит только при выселении по выбору кассира
- Чёрный список и предупреждения при заселении
- История проживаний, повторное заселение в 1 клик
- Кадастр: учёт регистраций, ежедневные напоминания о сроках

### 🔐 Персонал и доступ
- Роли: super / admin / кассир (по филиалу)
- Пароль проверяет Cloud Function `authenticateUser`: хеши (PBKDF2) лежат в закрытой коллекции `userSecrets`, клиенту недоступны
- Защита от подбора: 5 неудач → пауза 1 мин, 10 → 15 мин, 20 → час; счёт ведётся и по логину, и по IP
- Сессии устройств, смена пароля, авто-выход при бездействии
- Аудит-лог действий, история отмен
- Права на снижение цены, задачи

### 🖥 Интерфейс
- Глобальный поиск Ctrl+K, календарь занятости
- Два языка (русский/узбекский), темы, настраиваемое расположение меню
- Бета-режим: параллельный новый UI (календарь v2, «Сегодня», командная палитра) на тех же данных
- Аренда комнат целиком (посуточно, с продлением)
- Групповое заселение, лист в бухгалтерию

## 3. Интеграционный контур брони

| Шаг | Что происходит | Кто делает |
|----|----|----|
| 1 | Гость пишет боту / бронирует на сайте. ИИ-менеджер отвечает от имени владельца (Telegram Business), торгуется по правилам, распознаёт голосовые | сайт + ИИ |
| 2 | Бронь (код HS-XXXXXX) падает в MySQL и в приложение вместе с ИИ-сводкой переписки | сайт → Firestore |
| 3 | В приложении всплывает большое окно: телефон крупно, советы для звонка. Повтор каждые 6 часов | приложение |
| 4 | Кассир подтверждает → сайт ставит «подтверждена ✅», гость получает сообщение в тот чат, где бронировал | crm-callback |
| 5 | Гость приходит → заселение требует дополнить паспорт → «гость заселён 🏠», залог учтён | приложение |
| 6 | После оплаты гражданин Узбекистана автоматически регистрируется в e-mehmon в фоне | e-mehmon-автомат |
| 7 | Выселение / истечение срока → авто-вывод из e-mehmon, сверка каждые 5 минут | e-mehmon-автомат |

## 5. Данные (Firestore)

БД `hostella`, путь `artifacts/hostella-multi-v4/public/data/…`

| Коллекция | Содержимое |
|----|----|
| guests | Гости и брони: статусы `active / booking / checked_out / debt`, оплаты, e-mehmon-отметки, метаданные брони (bookingCode, channel, tgChatId, chatSummary, seatedCount) |
| rooms | Комнаты: вместимость, цены, occupied, аренда целиком |
| payments | Все платежи (нал/карта/QR/перевод/баланс) — база смен и отчётов |
| expenses | Расходы по категориям и филиалам |
| clients | База клиентов: паспорт, баланс, чёрный список |
| shifts | Смены кассиров: `shareRatio`/`shareGroupId` — доли при подмене и делении 50/50, `opening`/`openingFrom` — итоги смены, принятой при передаче |
| userSecrets / authThrottle | Хеши паролей (PBKDF2) и счётчики попыток входа. Закрыты правилами: пишет и читает только Cloud Function |
| registrations / cadastreRegistrations | Журнал e-mehmon и кадастр |
| manualStayGroups | Договоры: участники, периоды, бригады, extraCharges, переносы сальдо |
| bookingCom | Снимки iCal Booking.com по филиалам |
| settings | appConfig (цены, боты, интеграции), hostelConfig, шаблоны |
| users / sessions / auditLog | Персонал, устройства, действия |

## 6. Сайт hostella.uz и Telegram-бот

### Для гостей
- Бронирование на 3 языках (рус/узб/англ), оплата Payme/Click
- Проверка и самостоятельное изменение брони по коду HS-XXXXXX
- Блог, страницы филиалов, гид по Ташкенту, QR-страницы
- Реферальная программа «приведи друга»

### Telegram-бот (tg-bot.php)
- ИИ-менеджер: отвечает на языке клиента, ведёт к брони, торгуется по правилам, знает живую доступность мест
- Telegram Business — отвечает от имени владельца в его личных чатах
- Голосовые через Whisper, создание брони прямо из чата
- ИИ-сводка переписки для кассира при создании брони
- Акции/промо-цены, метки источников рекламы

### Связь с приложением
- Бронь сервером пишется в Firestore (две попытки)
- `crm-callback.php`: статусы обратно (подтверждена/отменена/заселён) + уведомление гостю в тот чат, где он бронировал
- Cloud Function `getFreeBeds` — живая доступность мест для ИИ
- Владельцу — алерты о новых бронях и изменениях
